# 内容与视觉规则

制作或大幅修改内容前读本页；输入字段见 [authoring.md](authoring.md)，成品复核见 [quality-review.md](quality-review.md)。品牌依据是本技能的 V5 模板、底板和字体。用户本轮确认的修改优先，其次是用户已确认稿件，再其次是本技能默认值；局部修改不自动改写整套品牌系统。

## 先确定叙事，再选布局

先用一句话写清受众、希望其作出的判断或行动、支撑这一判断的核心结论。按事实组织故事线，例如问题→证据→方案→行动；目录不能代替故事线。

每页只承担一个主要任务。标题优先写可直接说出口的结论，正文补充证据、口径和边界；正式答谢页之前必须有实质性的结论、决策或行动收束。内容超过六个独立观点时优先拆页。分析和方案页通常保留一个判断、关键证据、两三条解释及必要行动。

在项目 `plan.json` 或同等规划记录中逐页写出：结论 `claim`、证据 `evidence`、内容关系、阅读顺序、主视觉、信息密度及布局选择理由。先画无样式几何草图，再套品牌外壳。模块数由信息单元决定，不能先选三栏再凑三条；图标或颜色变化不算新的内容结构。

同一正文轮廓避免连续超过两页；超过八页的材料至少考虑三种清晰可辨的结构。先服务于叙事，不能为了形式变化打乱比较关系。用户要求保持的系列版式可持续使用，并在审阅中说明理由。

## 直接、具体的业务表达

按“具体对象 + 明确动作 + 结果或证据”起草。压缩顺序是删除重复背景、把过程改成结论、合并并列短语、保留改变判断的数字、将细节移到下一页或附录。

- “赋能、重塑、闭环”要展开为可观察动作，例如统一口径、缩短处理时间、触发任务、责任人回填结果。
- 避免“不是……而是……”“不仅……更……”“更智能、更高效、更安全”等修辞性反差和无证据排比。真实比较使用共同维度与事实；正常否定句如“测试未通过，暂不发布”可以保留。
- 删除“开启新篇章、打造新引擎、价值跃迁”等不能验证的口号及“随着……不断发展”等通用开场。没有数据时写清机制和边界，不补造数字。
- 法规原文、直接引语、正式品牌文案可以保留，逐项记录原文、来源和保留理由，不能全局豁免文案检查。

## 内容关系决定图形

| 读者要理解什么 | 优先选择 | 应避免 |
| --- | --- | --- |
| 趋势、差距、数量 | 柱/线图、可信关键数字 | 把无比较价值的年份或数量放大充数 |
| 少量方案的取舍 | 共同维度的比较表或矩阵 | 每个方案使用不同维度 |
| 真实顺序、因果、阶段、反馈 | 流程或时间关系图 | 给并列条件强加箭头或闭环 |
| 层级、系统、职责 | 层级图、架构、矩阵或泳道 | 将所有节点处理成等权卡片 |
| 产品行为、具体对象或场景 | 真实截图、官方资产、清晰照片 | 伪造界面、无关机器人/握手/科技光效 |
| 决策与行动 | 选项、标准、权衡、推荐；责任人、交付物、时间和验证方式 | 只有任务名，没有责任和结果 |

每个普通正文页至少有一个承载信息的视觉。填写该页 `visualTextBinding`：`supportsClaim` 是具体结论，`textAnchor` 是相邻标题或文字，`informationCarried` 是图形独立表达的证据、数量、顺序、因果、层级或比较。来源可写入 `sourceOrGeneration`。不能只写“美观、与主题相关、丰富页面”。Logo、底板、分隔线、无语义色块和装饰小图标不算信息视觉。文字说明含义，图形承担证据或关系，不能把同一长段文字截图后再显示一遍。

封面、目录、纯结束页不要求信息视觉。`text` 布局用于必须完整保留的法务、引文或用户明确要求的纯文字页；填写具体 `visualExemption`，不要把它作为普通分析页的默认答案。若暂时缺少证据，先补材料或用准确的关系图表达，不编造数据。

## 证据双区页

以下条件同时满足时，默认选择 `two-column` 的左解释、右视觉结构：一条结论可用两三条短解释说明；有独立承载证据或关系的主视觉；按标准字号可以清晰排下。左区约 35%–42%，右区约 58%–65%，栏隙单独计。左侧说明结论和含义，右侧图表、表格、关系图或截图说明证据。

多类别图表、大矩阵、长流程或多个同等重要对象确需更多空间时，使用全宽图表/表格或内容对应的图解。在规划中写 `layoutChoice` 的适用性、所选结构和具体理由。适用页采用双区的比例低于约 60% 时，复查替代理由；这是审稿提示，不是整稿硬配额。不得为比例造图或缩字。

解释标题 15pt 加粗，解释正文 12pt 常规、150% 行距；右侧图表/视觉标题 10pt 常规。按浏览器实际换行后的文字底边安排下一个对象，正文到下方结论块至少 16px；小标题到表格或图形外沿也至少 16px。图表为类别标签预留独立槽位，柱、点、数值标签不能侵入。浅蓝建议或结论框左对齐，左右内边距 10–14px。

## 品牌、字体与间距

- 固定画布使用资产清单的真实宽高，不替换成近似的默认 16:9。封面题名槽、右侧山水、底部 Logo、声明及留白沿用 V5；封面只改允许的文字，长标题先精简，不能移动图形或缩字救场。
- 顶栏标题沿用已校准的框位：23pt、白色、加粗、左对齐、单行，避开 Logo 前至少 16px。正文页必须保留标题条、Logo、页脚线、公司名、保密提示和页码，不能重复叠加品牌家具。
- 中文使用内嵌 EFund，英文与数字使用内嵌 EFundLatin（Arial）。字号由文本角色确定，不能自动缩字、换窄字体或依赖系统回退；文案放不下时精简、换布局或拆页。CSS 像素字号为 pt × 4/3。
- 正文、解释、注释、来源与建议左对齐；数字列右对齐；只有短节点标签、表头、指标数字和固定品牌短标签可居中。使用现有字号角色；扩展布局时普通正文至少 10pt，表格至少 9pt，来源/脚注通常 7–8pt，低字号内容须实际放大检查。
- 所有正文、图表、表格和来源必须停在页脚线上方至少 8px，通常底边不超过 y=488。来源使用模板预留的单行来源带，过长时缩短引用写法、移至图旁或拆页，不能向页脚挤压。
- 使用深蓝主焦点、浅蓝/浅灰支撑和无框对齐；谨慎黄只标一个关键风险或例外。禁止阴影、发光、渐变虹彩、多个等权深色焦点，以及用三块以上空心灰框组织普通正文。表格、泳道和确需表达边界的分区可保留弱线框。
- 同级模块共用边缘、尺寸、基线和间距，间距至少 12px；有正文的容器四侧内边距至少 10px。内容少时保留留白，不单独放大一列字号。自定义多模块布局在规划中列 `alignmentGroups`，检查对应边缘/宽高/间距，普通容差不超过 4px，表格网格不超过 2px。
- 连接线置于节点后方，除合法端点外避开文字外扩 8px 区域。右栏流程按节点、箭头及旁注的整个组居中；左右剩余空白差超过 max(32px, 栏宽×15%) 时重排。固定品牌页的留白不适用这条。
- 不用强制换行掩盖空间问题。正文一字汉字尾行须修复；两至四字短尾行逐项审阅，优先改写、按完整词组断行、调整列宽或拆页。

## 表格、目录与素材

表格依任务选型：任务清单回答“模块做什么”；分组重点表帮助定位对象和小计；紧凑比较表用于少量方案或指标。青色表头、白色粗体字，白/浅灰正文，无外框或纵向格网；任务清单可用细水平线，分组和紧凑表正文不画分隔线。通常只强调一个核心行；数值保持同单位、精度、正负号与右对齐。主体过密或表格挤占来源带时删减非关键行列或拆页，不缩到不可读。字段和当前支持的模式见 [authoring.md](authoring.md)。

分章长材料在每章正文前重复完整目录，仅高亮即将进入的章节；第一张目录对应第一章。章节名称、顺序和几何保持一致。目录保留原始首行位置、固定行高、青色编号和行下灰色虚线；首行上方不画线，少量章节保留下方留白。短单章材料可省目录。章节超过七项时调整层级或拆分导航，不拉伸或缩字。

优先本品牌已有合适素材、官方资产，再选择单一专业图标家族；记录素材来源，同级图标保持线性/面性、描边、尺寸、视角和颜色一致。禁用 emoji、字符图标、图标字体、AI 小图标替代品或多库混搭。真实图片与截图不拉伸，按目标比例裁切，主体与正文相向；必须检查裁切是否损失证据。当前构建器接收本地栅格图片，外部 SVG 图标需先安全渲染为图片，不能把活动 SVG 字符串塞入输入。

## 移植依据与边界

这些规则提炼自用户提供的 `efund-ppt-maker`：`authoring-guide`、`layout-design-playbook`、`writing-style-contract`、`design-system`、`table-layout-contract`、`typography-contract`、`cover-contract`、`toc-spacing-108` 及 `delivery-107/109/110/111`。来源副本只作开发参考，运行此技能不依赖它。

保留内容驱动的布局、图文绑定、实际换行与间距、无阴影、目录节奏和真实视觉验收。将 Shape ID、母版对象和 XML 字体检查改为 HTML 元素、计算样式、内嵌字体和浏览器渲染验证。V6 的 18pt 常规封面副标题、原生素材目录及案例页坐标没有移植；本技能继续使用用户指定 V5 的封面样式与资产。原生 PPT 的整页复制、OOXML 属性顺序、字体注册和母版维护不适用于 HTML 制作，最终 PPTX 的格式兼容性另按导出结果检查。
