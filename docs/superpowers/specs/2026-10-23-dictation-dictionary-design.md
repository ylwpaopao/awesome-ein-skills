# 听写词库 Skill 设计

## 目标与范围

从人工修订的会议纪要、原始转写或用户直接提供的纠错中，积累人名、机构名、项目名和行业术语，维护唯一主词库，再同步到 Typeless、PLAUD 中国区和 ChatGPT/Codex 的听写词典。

Skill 与词库分开存放。**只有主词库通过独立的 GitHub 私有仓库跨设备同步**。本 Skill 不管理 Codex 完整配置原有的 Git 备份、提交或同步方式。

会议正文按需读取，不另存一份。候选审核时展示必要上下文；词库只记录词条、常见误写、领域及来源链接/时间戳。

## 数据与实现结构

- Skill 名为 `dictation-dictionary`，置于仓库根目录；固定的数据校验、去重、差异计算、备份、配置编辑和 Git 操作使用脚本实现。
- 主词库默认位于 `~/.config/dictation-dictionary/vocabulary.json`；`~/.config/dictation-dictionary/` 就是独立私有 Git 仓库的本地目录，远端只同步主词库。每条包含稳定标识、正确写法、常见误写、领域、来源及启用状态；保留原始大小写，不混淆不同的合法词。
- 向三个目标分发时，只提取已确认、已启用词条的正确写法，作为完整的词或短语传入；常见误写、领域及来源不写入应用词典。
- 各设备默认使用上述固定路径，不增设“设备本地配置文件”。需要其他位置时，由调用参数明确指定词库路径。
- 备份默认位于 `~/.local/state/dictation-dictionary/backups/`；运行记录及临时导出文件放在同一状态目录下的独立子目录，均不属于主词库跨设备同步内容。
- 未确认候选不写入主词库。错误写法作为证据，不直接变成所有场景通用的替换规则。

## 每次运行的流程

1. 读取输入及应用现有词典。PLAUD 对比时明确使用原始版本，区分其优化转写和 AI 总结；人工纪要的改写、删节及事实修正不直接认定为识别错误。
2. 对词库仓库先获取远端引用，读取远端词库进行比较，不自动改写本地主词库。
3. 生成候选及完整变更预览：分别列出本地主词库、远端主词库、Typeless、PLAUD 中国区、Codex 的新增、修改、删除和无须变更项。默认合并、去重和补缺，不自动删除已有词条。
4. 由用户确认具体变更；一次确认可以涵盖明确列出的整批目标。仅确认词条正确、但未看到应用变更清单时，不视为已批准应用写入。
5. 每个目标每批变更前检查当前状态仍与预览一致，保存并核验旧状态备份，再执行已确认的写入。没有变化的目标不写入；备份失败不写入。
6. 写入后重新读取并核验。主词库的提交和推送只包含已经确认的词库变化；报告各目标成功、失败和待完成部分，不将生成导出文件等同于应用已同步。

初次导入现有应用词条、从远端更新本地主词库、修改/删除词条和恢复备份，同样需要先预览并取得确认。

## 三个应用的适配

| 目标 | 已核查依据与实现方式 |
| --- | --- |
| Typeless | 通过 macOS 无障碍控件读取桌面应用的词典，按“词典 → 新词”输入单个词或短语；批量时使用官方“导入 CSV”入口，先验证格式，再增量导入并读回核验。未验证可直接管理词典的公开 API，不直接编辑其内部数据库。 |
| PLAUD 中国区 | 本机 `web.plaud.cn` 已有“设置 → 自定义术语 → 常用术语”，新增入口只有术语输入框。优先在已登录浏览器中用 Playwright 的 DOM 定位读取词表并逐项增补；截图/坐标形式的 Computer Use 作为控件定位不可用时的后备。 |
| ChatGPT/Codex | 本机 `~/.codex/config.toml` 中的 `desktop.dictationDictionary` 是字符串数组。只替换该键的数组值区间，其余文件字节原样保留，不通过 TOML 整文件序列化写回；保留权限并重新解析、读回校验。配置已写入与应用运行时已生效分别报告，生效时机需实际验证。 |

网页及应用界面使用可用的正式工具操作；不得假设未验证的私有 API 或导出能力。若无法完整读取旧词库并完成备份，停止该目标写入，说明缺失条件。以上是拟采用的写入方案，目前只完成过实机只读查看。

PLAUD 接口边界（2026-10-23 核查）：

- 全球版[个人账号 API 说明](https://support.plaud.ai/hc/en-us/articles/60726890231449-How-can-I-get-API-access-to-my-Plaud-data)明确目前没有公开通用 API；[MCP 工具表](https://docs.plaud.ai/plaud-mcp-cli/mcp)没有词库管理工具。
- 全球 Embedded 的[提交转写接口](https://docs.plaud.ai/api-reference/transcription-api/submit-audio-for-transcription)支持单次转写的 `hotwords` 参数，这不等于修改个人 App/Web 的持久词库。
- [中国区用户协议](https://web.plaud.cn/terms-service/user-agreement-cn.html)说明了读取已有录音、转写和总结的 MCP 授权。尚未找到中国区词库读写 API 的公开官方文档，也未证实全球接口或凭据可用于中国区；不把“未找到文档”写成“只能通过界面操作”。

## 备份、并发与失败

- 每个目标每批实际写入前保存带时间及校验信息的旧状态；主词库与应用词典分别备份，默认保留，不自动清理。
- Codex 编辑前备份当时的配置文件，备份保存在本机并保留受限文件权限；该操作不改变用户既有的 Codex 配置 Git 管理流程。
- **Codex 内容保护是硬性约束**：写入前校验预览对应的完整文件版本；构建新内容后，逐字节确认除 `desktop.dictationDictionary` 数组值区间外完全一致，同时验证解析后的唯一变化也是该键。出现缺失、歧义或无法安全定位时停止，不顺带新增设置、安装 MCP、调整格式或其他配置。
- 从 Codex 备份恢复时，也只取回词典值并经过预览确认，不能整份覆盖当前 `config.toml`，避免撤销此后发生的其他设置变化。
- 预览后出现任何未覆盖的词库或配置变化，重新生成差异并确认；不强制覆盖、不强制推送。
- 执行失败即停止受影响目标，保留备份和已完成记录。后续重试重新读取状态，避免重复添加；恢复操作也需预览和确认。
- Git 失败、离线、登录失效或界面变化均明确报告。不得把部分成功报告为三端全部完成。

## 验收

- 脚本在隔离样例中验证中文、短语、重复词、合法同音词、来源合并、增量差异和重复运行。
- 验证未经确认不能写入，旧状态变化会拒绝执行，备份失败不改目标。
- 用临时配置验证仅词典数组值变化、区间外字节完全不变、TOML 有效、权限保留；验证恢复词典时保留备份之后发生的其他设置变化。不以实际用户配置作为测试写入对象。
- 验证主词库的辅助信息不会进入三端投递内容，默认词库与备份路径分离，不产生额外设备配置文件。
- 用临时 Git 仓库验证远端比较不改本地主词库，确认后的正常同步及并发拒绝；不通过强制推送消解冲突。
- 用用户示例形成第一批真实候选和各端变更预览；只有取得该批确认后才执行实际词库变更及读回核验。
- 更新根 README，提交并推送 Skill 开发成果；不夹带仓库已有的其他未提交工作。
