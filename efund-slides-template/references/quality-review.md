# 检查、视觉复核与交付

质量分为输入与构建、浏览器检查、逐页视觉判断、导出文件检查。任一层通过都不能替下一层背书。Bun 是执行脚本的运行时，不负责审美判断；结构化输入也不能保证任意长度和内容自动美观。

## 先完成 HTML

1. 按 [design-rules.md](design-rules.md) 规划，构建 HTML，再运行 `check.mjs`。检查失败则改文案或布局，重新构建和检查。保留用户输入原件，更新自己的输出时才使用覆盖选项。
2. 打开检查生成的每一页截图，以正常大小和必要的局部放大检查；总览只用于判断整篇节奏。封面与模板参考对照，最长标题、最密表格、负值图表、中英混排和“谢谢”等字形重点查看。
3. 核对每页主张、图表原始数据、单位、口径、日期与来源；逐条确认 `visualTextBinding`。删除装饰不能影响信息，删除信息视觉应明显损失证据或关系。
4. 修复后重新生成受影响截图；更改字体、底板、全局 CSS 或渲染器时检查全部页面。不要修改检查器来掩盖坏页面，也不要手写“通过”替代真实工具结果。

## 逐页判定

| 范畴 | 必须实际核对的内容 |
| --- | --- |
| 品牌与字形 | V5 标准封面、完整页头页脚、无重复家具；白色单行顶栏；中文/Latin 字形正确，无系统回退、方框或乱码 |
| 可读性 | 无裁切、溢出、遮挡或单字尾行；数字/单位可读；真实文字底边到下方视觉至少 16px，标签与数据标记不冲突 |
| 布局 | 唯一主焦点；正文左对齐、数字列右对齐；同级网格一致；流程组和两栏留白平衡；无阴影与空心卡片墙 |
| 内容与证据 | 一页一个判断；视觉与相邻文字对应；数据、截图和案例真实；没有示例数值、模板提示语或无依据口号混入正式材料 |
| 专用结构 | 表格模式与任务一致；分组/紧凑表无正文分隔线；目录行距紧凑，章节前完整导航且只高亮下一章 |
| 隐私 | 可见文本、截图、隐藏备注及交付元数据中没有本次不应交付的信息 |

浏览器脚本能验证字体、图片、运行错误、外部请求、尺寸与已实现的几何规则；内容提示只帮助定位疑点。任意图形的全部重叠、关系是否合理、数据是否真实、截图中的敏感信息和整篇节奏仍由 Agent 或人工观察。不把脚本未覆盖的要求写成“自动验证通过”。

## 留下真实审阅记录

从检查生成的 `visual-review.template.json` 复制到 QA 目录的 `visual-review.json`，保留当前 HTML 与逐页截图哈希。填写实际审阅方式 `method`（`image-capable-model` 或 `human`）、审阅者 `reviewer`，以及每页的 `observation`、`checks` 和 `verdict`。初始检查为 `null`，代表尚未观察，不能自动改成通过。

每页的 `hierarchy`、`layout`、`readability`、`evidence`、`privacy` 五项都须根据真实观察填写。全部确认且无待修改问题时才设为 `true`，`verdict` 才能为 `pass`；`observation` 写具体观察或已修复的问题。普通正文可附 `visualTextBinding` 说明核验结果。页码须完整、顺序与成品一致。

```bash
bun "$SKILL_DIR/scripts/verify-review.mjs" \
  --input "$PROJECT/slides.html" \
  --qa "$PROJECT/qa" \
  --review "$PROJECT/qa/visual-review.json"
```

验证器检查记录、文件哈希和页面是否完整，不替代视觉判断。HTML 或截图改变后，旧哈希记录不能继续证明新文件已审阅。脚本可以创建待复核模板，不能自动替观察者填写 pass。

结构失败、损坏字体、品牌缺失、正文侵入页脚、信息遮挡及错误数据必须修复。其他需要判断的提示逐页写明处理和理由；例如“第 4 页右侧是同单位的 12 类比较，使用全宽以保留标签字号”，不能只写“已检查”或“有意重叠”。缺少视觉能力或实际打开能力时保留未完成状态，说明限制，不能声称全部质量验收通过。

## 隐私和可移植性

按本次受众和交付范围确认哪些内容可以交付，保留任务需要的真实业务信息，不擅自改写数字或身份。外发、匿名样例或公开发布时，额外检查姓名、账号、联系方式、客户/项目代号、非公开指标、截图水印、本机路径、编辑者与备注；公开数据应有来源。

HTML 的 `notes`、可访问数据表、图片原始像素和内嵌资产都可被提取，隐藏不等于删除。敏感截图必须修改或替换底层图片，不能只盖一块可移除遮罩；替代图若使用匿名数据，要明确标注。文本搜索不能覆盖图片内容，仍须看图。排除项目缓存、日志、临时文件和集成配置，不把整个工作目录当成交付物。

默认字体、图片、CSS 和播放器应内嵌。检查无外部请求，并在不依赖开发机字体或路径的环境打开；缺失品牌字体应修复资产加载，不能静默替换成相近字体。素材修改或隐私清理后，重新验证最终文件及截图。

## PDF 与 PPTX 交付

用户即使只要求 PDF 或 PPT，也先制作、完成并验证 HTML，再从同一份最终 HTML 导出。转换不能成为绕开 HTML 质量检查的捷径；保留 HTML 作为可复现来源。命令以 [SKILL.md](../SKILL.md) 和 [authoring.md](authoring.md) 为准。

每个交付格式分别检查页数、顺序、实际纸张/画布、裁切、清晰度、字体和品牌家具。PDF 要打开并渲染查看；PPTX 要核对最终包与逐页图像，并用目标演示软件实际打开检查，不能将 HTML 截图冒充 PowerPoint 打开证据。任何修复提示、空白页、乱码或截断均需解决；没有目标软件时明确写“未完成目标软件打开复核”。

PDF/PPTX 默认以 HTML 的高分辨率整页图像封装：PPTX 正文不是原生可编辑的文本框/图表，PDF 文字不可直接选中或搜索。编辑内容回到 JSON/HTML 后重新导出。直接浏览器打印曾在两个 PDF 渲染器中复现品牌中文合成粗体缺笔，因此不作为当前正式交付路径。不要宣称无损矢量、原生可编辑、可搜索或各软件像素完全相同。导出方式和限制须与实际实现一致。

可在 QA 中追加各格式的文件哈希、使用的渲染器、实际打开结果与逐页观察。只记录做过的检查；导出文件变化后相应记录失效。最终回答列出用户要的产物、HTML 来源和未完成的实际检查即可，不用重复整套流程。
