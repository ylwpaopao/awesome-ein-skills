# 全文检索与下载

需要获取全文时读取。来源顺序固定为 Sci-Hub → SciDown，不询问用户选择来源。每次以当前页面为准；示范只覆盖了一种 SciDown 跳转，不能把该跳转地址或页面层数写死。

## 先查 Sci-Hub

1. 用 `uv run scripts/workflow_files.py domains` 读取 [域名记录](scihub-domains.json)，按记录顺序尝试。记录区分用户报告可用与本机实际验证，不能把前者说成已验证。
2. 普通 DNS、连接超时或网络封锁时记录 `network-unavailable` 并尝试下一个已记录域名。仅当全部记录域名均因这些网络原因失效时，搜索最新可用 Sci-Hub 域名，核对来源与实际页面后补充记录；不批量猜域名。
3. 页面实际加载且具有论文检索功能后记录 `available`，输入原始 DOI 检索。若出现对应全文，核对标题与作者，下载并进入文件验收。明确未收录则直接转 SciDown，不为同一 DOI 轮询全部镜像。

观察后用 `uv run scripts/workflow_files.py record-domain URL STATUS` 更新记录，`STATUS` 为 `available`、`network-unavailable` 或 `policy-blocked`。只有实际验证才写入 `available`；有检索页面不代表这篇论文已收录。

明确显示未收录、找不到全文或无对应文件时转 SciDown。DNS、网络错误、验证码或工具站点安全策略阻止不属于“未收录”。遇到工具策略拒绝立即停止该访问，不继续轮换域名或搜索镜像规避；记录原因，允许时检查 SciDown。验证码和浏览器警告按 [工具边界](browser-tools.md) 处理。

## 再查 SciDown

1. 优先用 Playwright 在 Chrome 打开 `https://www.scidown.cn/`，找到提示“支持DOI号，标题，作者，ORCID等”的搜索框，输入本次 DOI，点击“搜索”。如果进入 SciDownScholar Pro 检索页，确认 DOI 已填入，点击“检索”。
2. 核对结果的 DOI、标题与作者，检查可用全文入口。常见名称有“Open Access”“海外 OA”“下载”“CN Direct Download”，实际控件可能变化；选择通向论文全文的可用入口。
3. 每次点击后检查新标签页、当前 URL、页面内容和下载事件，再按下表处理。只跟随当前论文结果实际提供的链接；最终机构仓储 DOI 与期刊 DOI 不同时，父 item 仍使用原始期刊 DOI。

默认不打开“网盘离线下载服务条款与免责声明”详情页。当前下载动作已获有效确认时，直接勾选并继续；不反复展示全文。工具要求新的当次确认时仍须遵守，长期偏好不替代该确认。

| 当前状态 | 下一步与完成条件 |
| --- | --- |
| 直接触发下载 | 等待下载完成，取得本次文件的准确路径，进入文件验收。 |
| 浏览器 PDF 阅读器或内嵌 PDF | 核对文献身份，使用阅读器下载控件；文件已落盘才算下载完成。 |
| 机构仓储、作者主页或出版详情页 | 找到与当前论文匹配的全文/Accepted Manuscript/PDF 文件链接。HTML 详情页不是附件文件。 |
| 中转、网盘或临时取回页 | 核对论文信息，使用真实下载/取回控件；刷新状态后继续判断，不把本次 token 地址保存成固定 URL。 |
| 新窗口、多层跳转或 iframe | 检查当前结果实际打开的标签页或内嵌内容，通过可见控件或页面中的真实文件链接继续。记录已访问状态，避免循环。 |
| 登录、验证码、条款或系统认证 | 保留现场，按当前工具规则请求用户处理需要其介入的步骤，完成后继续。 |
| 不安全表单、证书或站点安全阻止 | 说明实际阻碍，遵守工具限制；浏览器安全警告由用户处理，不自动绕过。 |
| 广告、付费推广、错误页或与论文无关内容 | 返回当前论文检索结果，检查尚未尝试的实际全文入口。 |
| 相同页面循环或同一入口重复报错 | 检查其他已发现的候选入口；没有新候选时停止并报告阻碍，保留已有 item 和文件。 |

## 中断或隔日恢复

先按 DOI 核对已有父 item 和附件，保留原下载 session；不重新创建文献条目。用户已下载文件时，先按原 session 检查本次文件，再决定是否重新下载。

旧临时取回页报错时记录实际错误，不直接认定为过期，也不反复刷新旧页。需要重建下载状态时，从 SciDown 首页重新检索原 DOI，沿当前结果生成新的中转/取回入口；不猜旧 token 或临时文件地址。

若相同 URL 直接打开报“请求信息有误”，而经中转进入正常，应记录为地址不能单独重放、依赖前序请求状态，不声称已证实超时。保留当前取回标签页供用户继续，不只发送该 URL 让用户另开。

交接给用户时同时提供稳定首页、DOI、进入下载入口的步骤及待处理动作，临时页只作辅助。登录、条款、浏览器警告和工具策略限制继续按当前规则处理；工具拒绝的访问不通过换通道恢复。

## 文件验收

保存到 `prepare` 返回的任务目录，或本次浏览器下载的 Downloads 路径。若下载工具返回了本次任务新建的临时/缓存文件，复制到任务目录，并用 `register SESSION SOURCE --cache-origin CACHE` 同时登记工具返回的准确缓存路径；`finish` 验证独立副本后会清理两份任务下载文件。脚本拒绝本任务开始前就存在的缓存文件，此时改为发起本次新的下载，保留原缓存。不能凭“最近修改”挑选文件。

用 `check` 校验 PDF 签名，再打开首页核对标题和作者，匹配后用 `register` 记录文件身份。脚本会拒绝 HTML 冒充的 PDF，以及 Downloads 中本任务开始前就存在的文件。若验收失败，回到当前页面继续寻找实际 PDF，不能把扩展名或“下载成功”当作全文有效的证明。

同时核对版本、日期、期刊页码或工作论文编号。同名同作者的旧稿不等于期刊正式版；必要时用仓储的“Published Versions”等关系确认是同一研究。只有工作论文或作者稿时，除非用户已允许该版本，先说明版本差异并确认是否附加；允许后在附件标题注明版本与日期，保留父 item 的期刊 DOI 和元数据。检索成功不代表取得了正式版。

下载事件监听超时并不证明文件未下载：先检查实际下载记录，并用本次 session 的开始前快照排除原有文件，再决定是否重试。只获取论文 PDF，不使用结果页的 RIS/BibTeX 导出按钮。

回到主流程，为已核对的父 item 添加文件附件；确认 Zotero 已保存独立可读副本后，运行 `finish` 删除本次下载文件。
